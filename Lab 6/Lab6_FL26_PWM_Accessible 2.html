Objectives

  1. Write your own millisecond delay function.
  2. Write code using a 16-bit timer to control a DC motor's speed with a specific speed profile.

Introduction

In this lab, you will learn how to use the microcontroller to produce PWM signals. This signal will then be used in your next lab to control the speed of the DC motor available in your lab kit. You will need your datasheet, an oscilloscope probe from previous courses, an oscilloscope available in the lab, and LEDs.

Suggestion

You will make a millisecond delay function, which will be used for delays in other functions, including the speed profile function. This replaces the _delay_ms() function used before this lab. Make sure this function is working properly before attempting the other functions.

Make a secondary module consisting of a .c file and a .h file. Initialization and I/O should be included in the secondary module, not in main.

Speed Profile

Combine the previous steps to produce a speed profile that will control the DC motor in the next lab. The speed profile should be adaptable. It starts at X%, then ramps to Y% within a specified time, Z.

Example: The motor starts at a 15% duty cycle and slowly increases to 95% in 5 seconds using eight equally spaced steps. In your code, these values should be easy to change using variables instead of a formula. A different profile may be given during the check off.

After the speed profile, press the Stop PWM Output pushbutton to stop the motor. All PWM output is removed, and OC1A is returned to a normal I/O pin.

Use the Start pushbutton to start the profile and the Stop pushbutton to stop it. The profile can run once, then pressing Start again should run it again. Use the oscilloscope to observe the changes in the profile.

Set up a separate function to perform the speed profile:

void ramp_up_delay_n_steps(uint8_t start, uint8_t end, uint16_t ms_time, uint8_t num_steps)
start
Initial percent duty cycle
end
Final percent duty cycle
ms_time
Duration of ramping
num_steps
Number of increments used to increase or decrease the duty cycle

Part of the Pseudocode

  1. Calculate the change in duty cycle per step and store it as duty_cycle_change.
  2. Convert the duty cycle per step.
  3. Calculate the time for each step and store it as step_time.
  4. Loop for the number of steps.
    1. Make sure the OCR1A value is within the BOTTOM and TOP values.
    2. Change OCR1A.
    3. Delay for step_time.
  5. Return.

To turn off PWM output, change the compare output mode to normal port operation.

When changing status register values, make sure you do not erase values set during initialization.

Hints

  • At home, it may be difficult to verify operation. One way to test is to connect an LED with a current-limiting resistor. As the duty cycle increases, the LED should become brighter.
  • Simulation does not work well in this case. Make sure the calculations are correct and the preset values remain. Comment out the delays while leaving the code that sets the values so you can verify proper timer operation.
  • Do not write all the code at one time. Test the PWM function first, then leave it alone. Test the 1 ms timer, then leave it alone. Call the functions that you know work.
  • Use the Debugger to make sure the PWM initialization function works correctly.
  • The 1000 ms delay can prevent the Start pushbutton from being read. Hold the pushbutton until the flashing LED stops. This indicates that the code is in the PWM ramp function. The flashing LED acts as a diagnostic lamp that identifies the portion of code being executed and when the pushbutton is being read.
